## Q2：你用 Claude Code 做项目的时候有什么样的流程？
1. **确定需求写文档**：首先我觉得最重要的一步是确定好需求，写好需求文档。这体现在我在做项目之前就会构思好这个项目的最小可用版本（MVP 版本）到底要实现什么样的功能、用哪些技术、用什么样的架构实现、数据库怎么设计、实现了之后如何测试等等，然后形成一份 README.md 和 CLAUDE.md。我认为有这两个明确的文档是十分重要的。当然，这两个文档的写作不一定需要完全手打，也可以借助 claude code。
2. **搭建代码脚手架**：我会评估这个项目的复杂性，然后在 IDEA 中搭建脚手架。如果我觉得我可以手动做这个工作，我会用 IDEA 的初始化的功能来做；如果不能，就让 Claude Code 来做。这一步的时候，就可以开始用 **git** 做版本管理了，配置好远程仓库和工作分支。
3. **构建 MVP 版本**：拆分功能，让 Claude Code 逐步去实现每个部分。每个部分做完了，需要进行接口测试，一般是用 knife 4 j 这个文档工具来实现。在这个过程中，我会用到一些 skills 来协助，例如有一个 code-review 的 skill，让它来检查这部分代码的健壮性、是否有 magic words 或者 hard coding，是否泄露了例如 API Key 等的敏感信息。也有一个 frontend-design 的 skill，让它根据我的后端的新接口完善前端。同时，还有一个 git-commit 的 skill，帮我检查并提交代码。另外，我也用到一些 Hooks，在 settings.json 中配置的。例如，我配置了让它在 BeforeToolCall 的时候自动跑一次 mvn compile 来检测编译错误、检查格式、调整 CLAUDE.md 的内容等。

## Q3: 什么是 Harness？
Harness 是 Agent 系统的执行引擎，是用户输入与 LLM 之间的一层环境，它负责解析结果、调用工具、触发 Hook 等等。用户设置的 permission mode 是由它强制执行的，它也在记录着上下文、工作目录、任务列表等。在自己开发的 Harness，它还做执行隔离的工作，确保 Agent 的运行环境的安全、存在在沙箱中。
