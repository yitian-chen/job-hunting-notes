## 一个表中三个字段 A B C 建立了联合索引，当执行 SQL 的 `WHERE B > 10 AND A = 1 AND C < 20` 时，这个索引生效了哪几个字段？如何判断？
首先，优化器会自动把 WHERE 条件重新排列，匹配索引顺序：A = 1 AND B > 10 AND C < 20
然后按照**最左前缀原则**逐步匹配。
一旦某一列用了范围查询，后续的都无法走索引了。

因此，只用了 A 和 B，C 没有生效。

## 在前面那句语句执行时，Server 层和存储引擎层分别做了哪些查询操作？
**Server 层：**
	1. 解析器：解析 SQL，变成语法树，识别出表名、列名、条件。
	2. 优化器：决定用哪个索引，并对 WHERE 条件重排。
	3. 执行器：逐行调用 InnoDB，找符合 A = 1, B > 10 的下一行。

**存储引擎层：**
	1. B+ 树定位，找到 A = 1, B > 10 的索引位置。
	2. 索引条件下推，筛选 C，满足的才返回给 Server 层。
	3. 回表，先在联合索引中找到对应主键，再到主键索引取完整的行。
	4. 行锁，如果这条是 FOR UPDATE，返回时加 Gap Lock。

## MVCC 快照是怎么实现的？是复制了一份数据吗？
不是复制，而是同一行数据存在多个版本，每个事务通过可见性规则决定看到哪个版本。是用 Undo Log 串起来的。
ReadView 是沿着 Undo Log 往回走，比对事务 ID，确定到可见的记录。

## 消息队列与阻塞队列的区别

|     | 消息队列        | 阻塞队列(BlockingQueue) |
| --- | ----------- | ------------------- |
| 范围  | 跨进程、跨实例     | 同一个 JVM 进程内         |
| 存储  | 独立中间件，磁盘持久化 | JVM 堆内存             |
| 消费者 | 多个实例        | 同一进程内的多个线程          |
| 协议  | TCP 网络通信    | Java 内存操作           |

## 当注册中心不可用时，客户端如何合理的从本地缓存中选择服务实例，保证可用性和正确性？
Nacos 客户端可以处理。Nacos 内置了两层缓存，注册中心挂了之后自动从本地缓存读取。

**第一层：内存缓存（实时更新）**
	Nacos 首次查询服务列表时，会主动拉取地址，缓存到 JVM 内存。服务变更时 Nacos 推送通知更新，超过一定时间再全量拉取做兜底。
**第二层：本地文件快照**
	Nacos 把服务列表持久化到了磁盘上，重启时如果 Nacos 还不可用，就从本地文件快照恢复服务列表。

## 什么是 binlog
是 MySQL Server 层记录的逻辑日志，记录的是“做了什么 SQL”，而非数据的旧值。

有三种格式，一种记录原始 SQL，一种记录每行更改前后的值，一种混合。

可以用来做主从同步。

## 请介绍一下 Spring 的动态代理
作用：在运行时把方法调用拦截下来，插入额外的逻辑，再调真实方法。

两种：
- **JDK 动态代理**：类实现了接口，Spring 生成了一个实现相同接口的代理对象，调用者拿到 Service 的引用，实际上拿到的是代理。
- **CGLIB 代理**：类没实现接口，Spring 用 CGLIB 在运行时继承这个类，生成一个子类代理。

## 死锁是什么？
两个线程各自持有一把锁，同时又在等对方释放那把锁，循环等待。

破解：加锁顺序统一，所有代码按照统一顺序加锁，打破循环等待；自动检测，发现循环等待，直接回滚其中一个事务。
