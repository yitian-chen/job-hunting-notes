## Q：Java 和 C++ 有什么区别？
Java: 源码 -> 字节码 -> JVM 解释/编译
C++：源码 -> 机器码 -> 直接执行

|      | Java             | C++           |
| ---- | ---------------- | ------------- |
| 内存管理 | 自动 GC            | 手动 new/delete |
| 平台依赖 | JVM 跨平台，一次编译到处运行 | 需要为不同平台重新编译   |
| 指针   | 没有指针，只有引用        | 有指针和指针运算      |

## Q：说说 JDK 的版本，讲讲新版本的技术
- JDK 5: 泛型、注解、枚举、自动装箱拆箱、JUC、foreach
- JDK 8: Lambda、Stream API、Optional
- JDK 11：HTTP Client、ZGC、Flight Recorder
- JDK 17: 密封类、Record、Switch 增强
- JDK 21: 虚拟线程（由 JVM 管理的轻量级线程

JUC：Java 并发工具包，java.util.concurrent，包含 ThreadLocal, Lock, ConcurrentHashMap 等。
Optional：回避运行时的空指针异常，可用 Option\<object>来表达类可能为空。
HTTP Client: JDK 原生的 HTTP 客户端，做 HTTP 调用。
ZGC：低延迟 GC，在垃圾回收时暂停所有应用线程的时间很短。
Flight Recorder：内置的JVM 性能监控与分析工具。
Record：可替代数据载体类的 class，自动生成构造器, equals(), hashCode(), toString(), getter()等。

## Q：虚拟线程如何实现？
由传统的 1 : 1 调度变成了 M : N。
虚拟线程遇到阻塞操作（IO、锁、Thread.sleep 等）时，不阻塞载体线程。阻塞结束后，JVM 找到空闲的载体线程后把虚拟线程挂上继续执行。

## Q：介绍一下 Stream API
采用声明式的方式处理集合数据。
```
List<String> result = userList.stream()
.filter(user -> user.getAge() > 18)
.map(user -> user.getName().toUpperCase())                             .toList();
```

使用上的限制：
1. 只能消费一次
2. 不能复用集合里的元素，即不能 `stream.get(3)`
3. 难以处理异常
4. 调试困难，难打断点。只能用 peek 来调试
5. 并行流有隐形的线程安全问题，需要用线程安全的容器
6. 性能开销较大，对超简单操作更慢。

## Q：讲讲缓存穿透
即请求的数据在缓存和数据库里都不存在，每次请求都穿透缓存打到数据库。

如果这样的请求量大了，DB 会被空查询搞崩溃。

解决办法：
1. 缓存空值，设置 TTL 较短即可。
2. 引入 Bloom Filter，请求来之前先过过滤器，不存在的数据直接拦截。
3. 参数校验，拦截明显不合法的请求。

## Q：讲讲限流方式
1. 第一层：Gateway 路由级限流。用 Sentinel 配置了 4 条 QPS 流控规则，对各个服务的流量设置上限，被限流的请求不会穿透到下游服务，直接返回 429。
2. 第二层：业务级限流：对 login 接口限流，防止暴力破解；50%慢调用则熔断 10 s

## Q：说说 Spring IOC 容器的初始化过程？
就是把配置文件（XML/注解/配置类）解析成 BeanDefinition，然后按照依赖关系实例化出所有的 Bean。

1. 定位：扫描包下所有的@Component、@Service、@Controller、@Repository 的类。还要读取自动配置类。
2. 加载：把类解析成 BeanDefinition（一个描述 Bean 的元数据对象），只描述不创建对象。
3. 注册：将上述的 BeanDefinition 注册，知道哪些 Bean 可以创建了。
4. 实例化：通过反射调用构造器、依赖注入等。
