## Q1: HashMap 底层的原理？
- 在 JDK 1.7 之前，HashMap 的数据结构是**数组**和**链表**，把每个键(Key)通过哈希算法映射到数组中的槽位。如果发生哈希冲突，则以链表的形式存储在同一个槽位上。这样，当哈希冲突严重时，效率很低。![[截屏2026-05-26 11.23.01.png]]
- 在 JDK 1.8 之后，作出了优化。当某个槽位的链表长度 >= 8，且哈希表数组长度 >= 64，则会把哈希表转化为**红黑树**，把在此 bucket 处的查找时间降低为 O(log n)。如果数组长度较短，< 64，则只会触发扩容，而不会立刻树化。相反地，如果在 resize 的时候，某个 bucket 的节点数 <= 6 了，则会把红黑树退化成链表。![[截屏2026-05-26 11.27.24.png]]

**哈希冲突**：两个 key 通过哈希函数计算得到了相同的索引。为了避免，需要设计优秀的哈希函数（具有雪崩效应），引入扰动函数。

## Q2: HashMap 为什么不是线程安全的
当两个线程**同时**向**同一个槽位** put 时，若都判断此位置为 null，则都会写入，后线程会**覆盖**前线程写入的数据。当多个线程同时触发树化或红黑树拆分，由于**没有锁保护**，红黑树的内部颜色属性和左右子节点指针会被错乱赋值。

###### 解决办法：
采用 `ConcurrentHashMap`，采用 CAS + synchronized 锁住桶节点。CAS 在桶为空时生效(此时无锁)，放入新节点时如果失败，则重试；synchronized 对当前桶的头节点加锁。

## Q3: 什么是 Hashtable？和 HashMap 有什么区别？
Hashtable 是 Java 老版本的一种线程安全的哈希表，本质上和 HashMap 一样，都是数组 + 链表 + 红黑树。区别如下：

|         | Hashtable              | HashMap   |
| ------- | ---------------------- | --------- |
| 线程安全    | 全部方法均采用 `synchronized` | 不安全       |
| 允许 null | key 与 value 都不能为 null  | 都可以为 null |
| 初始容量    | 11                     | 16        |

实际开发中，已经基本不用了。它是粗暴的全局锁，所有读写方法都加同一个锁，导致并发性能极差。可以用以下的集合进行替代：
- `ConcurrentHashMap`：线程安全。运用分段锁与 CAS，性能好很多。
