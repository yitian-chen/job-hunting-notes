## Q1: 重载(Overload)与重写(Override)的区别
重载：同一个类中多个方法有**相同的名字**，**不同的参数**列表；
重写：父子类集成或接口实现中，子类**重新定义**父类中**已有的方法**。

## Q2: JVM 垃圾回收
垃圾回收自动释放不再被程序引用的对象所占用的内存，减少内存泄漏和内存管理错误的可能性。

###### 触发情景：
1. **内存不足时**：JVM 检测到堆内存不足，无法为新对象分配内存时，会触发；
2. **手动请求**：`System.gc()` 或 `Runtime.getRuntime.gc()` 建议 JVM 执行，但不能保证立即执行。

###### 判断垃圾的方法：
1. **引用计数法**：每个对象有一个引用计数器，每当有一个地方引用它，计数器++；引用失效时，计数器--。当计数器为 0 时，表示对象不再被任何变量引用，可以被回收。缺点：无法解决循环引用的问题。
2. **可达性分析算法**（主要）：从一组 GC Roots 的对象出发，向下追溯它们引用的对象，以及其引用的其他对象。如果一个对象到 GC Roots 没有任何引用链，则这个对象可以被回收。
![[截屏2026-05-18 20.09.34.png]]

###### 垃圾回收的算法：
1. **标记-清除算法**：先通过可达性分析标记需要回收的对象，然后统一回收。缺点：效率不高；清除后空间碎片化。
2. **复制算法**：将内存分成两块，先用其中一块，内存不够时，将所有无需清理的复制到另一块，然后清理掉原来的那一整块内存。缺点：内存利用率很低。
3. **标记-整理算法**：可达性分析标记后不会直接清理，而是将所有存活对象移动到内存的一端，移动结束后直接清理掉剩余部分。优点：无内存碎片，适合老年代。
4. **分代回收法**：将内存划分成新生代和老年代，分配依据为对象经历过的 GC 次数。对新生代对象，采用复制算法；对老年代对象，采用标记-整理算法。

###### 标记-清除算法导致大量内存碎片，无法找到足够大的连续空间来分配大对象时的办法：
- **担保机制与晋升机制**：若是年轻代发生这种情况，会尝试将存活对象采用复制算法，或直接晋升为老年代。
- **触发 Full GC**：若老年代碎片化，无法容纳新晋升的对象或直接分配的大对象，会触发 Full GC。此时 CMS 这种基于标记-清理的收集器，会启动**碎片整理(Compact)**，将存活对象移向内存一端并擦除碎片。

## Q3：线程和进程的区别有什么？
- **进程**：操作系统资源分配和调度的基本单位，每个进程都有自己的独立内存空间，是程序在计算机上的一次执行活动。
- **线程**：CPU 调度与执行的基本单位。

线程是进程内部的执行路径，是进程的一个实体。

## Q4: 讲讲 Java, Python, Go 三者的区别

|      | Java      | Python      | Golang   |
| ---- | --------- | ----------- | -------- |
| 语言类型 | 编译型 + 解释型 | 解释型         | 编译型      |
| 运行载体 | JVM 虚拟机   | CPython 解释器 | 二进制机器码   |
| 性能表现 | 很高        | 较低(运行时动态解析) | 极高（接近 C） |
三种语言的并发模型的区别：
- **Java**：线程（Thread）与操作系统内核线程是一对一映射的，切换开销较大；依赖 java.util.concurrent 包，通过锁和线程池来管理并发。
- **Python**：由于 GIL（全局解释器锁）的存在，Python 在同一时刻只能有一个线程在 CPU 上运行，无法利用多核优势，高并发依赖多进程。
- **Go**：原生支持协程（Goroutine），极其轻量，切换开销极小，很适合高并发开发。

三种语言的选型：
- **Java**：适合大型分布式、高并发系统。有成熟的生态、工具链和微服务框架。
- **Python**：适合人工智能、数据分析、自动化脚本，开发效率高，适合算法和科研。
- **Go**：适合云原生、微服务基础设施、网络中间件开发。

## Q5: 解释型语言和编译型语言的区别：

|      | 编译型                    | 解释型           |

## Q6: JVM, JDK, JRE 的区别
- JVM 是 Java 虚拟机，是 Java 程序运行的环境，负责将字节码解释或编译成机器码，并执行程序。提供内存管理、GC 等功能，使 Java 具有跨平台性。
- JDK 为 Java 开发工具包，包含 JVM，编译器(javac)，调试器等开发工具，以及一系列的类库。提供开发、编译、调试、运行 Java 程序的全部工具和环境。
- JRE 是 Java 程序运行所需的最小环境，不包含开发工具。

## Q8：说说 JDK 的版本，讲讲新版本的技术
- JDK 5: 泛型、注解、枚举、自动装箱拆箱、JUC、foreach
- JDK 8: Lambda、Stream API、Optional
- JDK 11：HTTP Client、ZGC、Flight Recorder
- JDK 17: 密封类、Record、Switch 增强
- JDK 21: 虚拟线程（由 JVM 管理的轻量级线程）

**JUC**：Java 并发工具包，java.util.concurrent，包含 ThreadLocal, Lock, ConcurrentHashMap 等。
**Optional**：回避运行时的空指针异常，可用 Option\<object>来表达类可能为空。
**HTTP Client**: JDK 原生的 HTTP 客户端，做 HTTP 调用。
**ZGC**：低延迟 GC，在垃圾回收时暂停所有应用线程的时间很短。
**Flight Recorder**：内置的 JVM 性能监控与分析工具。
**Record**：可替代数据载体类的 class，自动生成构造器, equals(), hashCode(), toString(), getter()等。

## Q9：虚拟线程如何实现？
由传统的 1 : 1 调度变成了 M : N。
虚拟线程遇到阻塞操作（IO、锁、Thread.sleep 等）时，不阻塞载体线程。阻塞结束后，JVM 找到空闲的载体线程后把虚拟线程挂上继续执行。

## Q10：介绍一下 Stream API
采用声明式的方式处理集合数据。
```Java
List<String> result = userList.stream()
	.filter(user -> user.getAge() > 18)
	.map(user -> user.getName().toUpperCase())                           .toList();
```

使用上的限制：
1. 只能消费一次
2. 不能复用集合里的元素，即不能 `stream.get(3)`
3. 难以处理异常
4. 调试困难，难打断点。只能用 peek 来调试
5. 并行流有隐形的线程安全问题，需要用线程安全的容器
6. 性能开销较大，对超简单操作更慢。

## Q11: Synchronized 的底层原理是什么？CAS 是什么？
synchronized 锁信息存储在 Java 对象头的 Mark Word 里。

有如下的升级路径：无锁 → 偏向锁 → 轻量级锁 → 重量级锁
- **偏向锁**：只有一个线程反复进入同步块时，Mark Word 记录这个线程 ID。同一线程再次进入时不需要 CAS 操作——省去了加锁开销。
- **轻量级锁**：第二个线程竞争时，偏向锁撤销。线程在自己的栈帧里创建 Lock Record，通过 CAS 尝试把 Mark Word 改成指向自己栈帧的指针。CAS 成功 = 拿到锁，失败 = 自旋等待。
- **重量级锁**：自旋超过一定次数后升级。Mark Word 指向 ObjectMonitor 对象（C++ 实现），线程挂起进入内核态等待队列。依赖操作系统的互斥量。

**CAS** 是 CPU 层面的原子操作指令，确保原子性：（内存地址 A，旧值 B，新值 C）如果 A 当前的值 == 旧值 B，则把 A 改为 C，否则就不改。

## Q13: 解释一下线程池，线程池的核心参数有哪些？
线程池是预先创建一批线程，等着分配任务，而不是每次需要的时候再创建。线程每次创建和销毁都有很大的开销，因此线程池可以优化性能。

核心参数有：
1. 核心线程数（一直活着的线程数，即使空闲不会被回收）
2. 最大线程数
3. 空闲存活时间（线程空闲时间如果超过，就被回收，但当线程数低于核心线程数时不回收）
4. 任务队列
5. 线程工厂
6. 拒绝策略（抛异常 / 调用者自己跑 / 静默丢 / 丢最旧的任务）
