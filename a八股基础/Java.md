## Q1: 重载(Overload)与重写(Override)的区别
重载：同一个类中多个方法有**相同的名字**，**不同的参数**列表；
重写：父子类集成或接口实现中，子类**重新定义**父类中**已有的方法**。

## Q2: HashMap 底层原理
![[截屏2026-05-18 19.21.59.png]]
HashMap 是**数组 + 链表 + 红黑树**。首先用哈希算法（取余），将键值对的 Node 放进数组中的对应索引。当桶（数组中的一个格子）内的链表长度 >= 8 且数组容量 >= 64 时，会把链表转化为红黑树。

**哈希冲突**：两个 key 通过哈希函数计算得到了相同的索引。为了避免，需要设计优秀的哈希函数（具有雪崩效应），引入扰动函数。

## Q3: HashMap 为什么不是线程安全的
当两个线程**同时**向**同一个槽位** put 时，若都判断此位置为 null，则都会写入，后线程会**覆盖**前线程写入的数据。当多个线程同时触发树化或红黑树拆分，由于**没有锁保护**，红黑树的内部颜色属性和左右子节点指针会被错乱赋值。

###### 解决办法：
采用 `ConcurrentHashMap`，采用 CAS + synchronized 锁住桶节点。CAS 在桶为空时生效(此时无锁)，放入新节点时如果失败，则重试；synchronized 对当前桶的头节点加锁。

## Q4: JVM 垃圾回收
垃圾回收自动释放不再被程序引用的对象所占用的内存，减少内存泄漏和内存管理错误的可能性。

###### 触发情景：****
1. **内存不足时**：JVM 检测到堆内存不足，无法为新对象分配内存时，会触发；
2. **手动请求**：`System.gc()` 或 `Runtime.getRuntime.gc()` 建议 JVM 执行，但不能保证立即执行。

###### 判断垃圾的方法：
1. **引用计数法**：每个对象有一个引用计数器，每当有一个地方引用它，计数器++；引用失效时，计数器--。当计数器为 0 时，表示对象不再被任何变量引用，可以被回收。缺点：无法解决循环引用的问题。
2. **可达性分析算法**（主要）：从一组 GC Roots 的对象出发，向下追溯它们引用的对象，以及其引用的其他对象。如果一个对象到 GC Roots 没有任何引用链，则这个对象可以被回收。
![[截屏2026-05-18 20.09.34.png]]

###### 垃圾回收的算法：
1. **标记-清除算法**：先通过可达性分析标记需要回收的对象，然后统一回收。缺点：效率不高；清除后空间碎片化。
2. **复制算法**：将内存分成两块，先用其中一块，内存不够时，将所有无需清理的复制到另一块，然后清理掉原来的那一整块内存。缺点：内存利用率很低。
3. **标记-整理算法**：可达性分析标记后不会直接清理，而是将所有存活对象移动到内存的一端，移动结束后直接清理掉剩余部分。优点：无内存碎片，适合老年代。
4. **分代回收法**：将内存划分成新生代和老年代，分配依据为对象经历过的 GC 次数。对新生代对象，采用复制算法；对老年代对象，采用标记-整理算法。

###### 标记-清除算法导致大量内存碎片，无法找到足够大的连续空间来分配大对象时的办法：
- **担保机制与晋升机制**：若是年轻代发生这种情况，会尝试将存活对象采用复制算法，或直接晋升为老年代。
- **触发 Full GC**：若老年代碎片化，无法容纳新晋升的对象或直接分配的大对象，会触发 Full GC。此时 CMS 这种基于标记-清理的收集器，会启动**碎片整理(Compact)**，将存活对象移向内存一端并擦除碎片。

## Q5：线程和进程的区别有什么？
- **进程**：操作系统资源分配和调度的基本单位，每个进程都有自己的独立内存空间，是程序在计算机上的一次执行活动。
- **线程**：CPU 调度与执行的基本单位。
线程是进程内部的执行路径，是进程的一个实体。

## Q6: 讲讲 Java, Python, Go 三者的区别
|      | Java      | Python      | Golang   |
| ---- | --------- | ----------- | -------- |
| 语言类型 | 编译型 + 解释型 | 解释型         | 编译型      |
| 运行载体 | JVM 虚拟机   | CPython 解释器 | 二进制机器码   |
| 性能表现 | 很高        | 较低(运行时动态解析) | 极高（接近 C） |
三种语言的并发模型的区别：
- **Java**：线程（Thread）与操作系统内核线程是一对一映射的，切换开销较大；依赖 java.util.concurrent 包，通过锁和线程池来管理并发。
- **Python**：由于 GIL（全局解释器锁）的存在，Python 在同一时刻只能有一个线程在 CPU 上运行，无法利用多核优势，高并发依赖多进程。
- **Go**：原生支持协程（Goroutine），极其轻量，切换开销极小，很适合高并发开发。

三种语言的选型：
- **Java**：适合大型分布式、高并发系统。有成熟的生态、工具链和微服务框架。
- **Python**：适合人工智能、数据分析、自动化脚本，开发效率高，适合算法和科研。
- **Go**：适合云原生、微服务基础设施、网络中间件开发。
