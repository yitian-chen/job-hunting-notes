## Q1: 对 Git 的掌握程度如何？

- 远程仓库：将代码同步在 GitHub，确保工程的安全性、允许多人合作。
- 项目经验：曾独立用 Java 完成过一个 Gitlet，能实现 Git 的基本功能，通过 Java 的集合来实现。

## Q3：对 Docker 的掌握如何？
主要用于两个场景：编写 Docker Compose 来编排中间件，和为自定义组件写 Dockerfile。

我的这个项目靠一个 docker-compose 管理了 6 个中间件：MySQL, Redis Stack, RabbitMQ, MinIO, Nacos, Sentinel Dashboard。所有依赖直接可以通过运行 `docker-compose up -d` 一条命令全部拉起来，很快就能让开发环境就绪。
我给每个服务都挂载了数据卷，数据存在本地，防止数据丢失；关键信息不硬编码在 compose 文件里，而是通过环境变量的形式写在 .env 文件中。
我能看懂容器日志，来排查问题。

## Q4: 有没有部署过项目？怎么部署的？
使用两台 Linux 虚拟机 VM 1 和 VM 2，其中 VM 1 部署前端和 **Nginx**，暴露在公网中；VM 2 配置后端服务和基础设施（数据库与中间件，可用 Docker 部署）。

前端无需知道后端 IP，都交给 Nginx 做反向代理。当请求前端资源时，直接返回；请求后端接口时，由 Nginx 转发到 VM 2 的 Gateway，再转接到对应的服务。
Gateway 到下游服务这一段需要 Nacos 做服务发现。

## Q6: 你的项目采用的是 MVC 架构还是 DDD 架构？
MVC：分层架构，核心思想是关注点分离，由 controller -> Service -> Mapper 结构组成。
DDD：领域驱动设计，核心思想是业务逻辑本身就是架构的中心，代码结构要反映业务领域的边界。

我的项目是典型的 MVC。
- Controller 只做参数校验和调用 Service
- Service 层集中业务逻辑
- Mapper 层全部是 SQL 映射，不写业务规则
- 跨服务通信走 MQ，防止 Service 层之间直接耦合

## Q7: 流量控制的阈值是怎么来的？如何压测？
压测分三类：HTTP 接口压测、全链路压测、数据库压测。

HTTP 接口压测：
- JMeter：老牌，适合复杂场景，但并发量大时（超过 1000 线程）容易自己崩溃。
- wrk：极轻量，用 C 写的，百万并发都可，但不支持复杂场景编排。

数据库压测：
- sysbench：MySQL 官方的性能测试工具，直接在数据库上跑 OLTP 负载。

全链路压测：
- JMeter：能做，但重量级。
- Locust：特点是分布式，多台一起压，适合模拟真实用户行为。

## Q8: 在使用 Claude Code 的时候，有什么进阶用法吗？
### Skills：
- `/code-review`：检查最近改动的代码质量。先审查 P0 级安全漏洞（例如 SQL 注入、逻辑错误、数据泄漏风险），然后审查 P1 级漏洞（例如性能问题、缺失的异常处理、测试覆盖率不足），然后审查 P2 级漏洞（代码可读性、代码重复）。最后给出一个总体评分和一句话总结。
- `/git-commit`：规范提交当前改动。先分析改动类型，然后检查是否有.env 被暂存、密钥或 token、没有 console.log 调试用代码。
- `/feature-ship`：通过 Skills 串联来实现。先进行代码审查（前面的 code-review），然后测试验证（调用测试方法），然后 git 提交（调用 git-commit），然后自动创建 PR 并返回 PR 链接。

### Hooks：
- 自动编译：AfterToolCall: mvn compile
- 防密钥泄露：BeforeToolCall: grep -qn 'sk-'
